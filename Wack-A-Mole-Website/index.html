What this is

I built the whole game as one file, Wack.html. Open it in a browser and play. There is no build step and no second file to lose.

One chain of peep() calls runs the moles. A mole stays up for a random time between 500 and 1500 milliseconds, drawn by randomTime(500, 1500) in the code, and the same hole never comes up twice in a row. A whack hides the mole at once but does not touch its timer, because clearing that timer would kill the chain and stall the game.

In the game itself the mole is a hedgehog character. I had no mole I liked at that size, and the class name stayed mole because the logic is about the role, not the animal.

The board, drawn from the game

Three rows of three holes, built by createHoles in Wack.html. One mole up at a time.

Play it

Open Wack.html in a browser and press start.

Project history, stated plainly

Deep Wave 1 found a real bug here. onAuthStateChanged can call setupGame() twice, and the second call stacked a second grid click listener, so every whack scored twice. setupGame() now returns early once it has run. The same pass cut five unused Firestore imports, a timer variable that was cleared but never assigned, and a holes query that ran before any hole existed.

Honest notes

The high score board is optional. The page looks for Firebase configuration supplied by its hosting (__firebase_config and friends). With no config, which is the case for the plain file on its own, the game runs the same and scores are not saved anywhere.

I verified this site by reading Wack.html in full and by running node --check on its extracted module script, which passed. I did not play the game in this pass because no browser is available here, and I am not claiming a play test I did not do.
