Wack-A-Mole

One HTML file is the whole stall: open it, and the game is already running its nine holes.

Open the repo The high score board

Bay one: how to play

Open Wack.html in a browser and play: that single file is the whole game. Nine holes are built by the script in a three by three grid, two columns on narrow screens but still nine holes, so a phone does not get an easier game. A round lasts 30 seconds, each successful hit scores one point, and the creature stays up for a random time between half a second and a second and a half. The cursor over the board is a small hammer.

A note the code itself makes: the animal shown is a hedgehog, chosen because it reads well at that size, while the class name in the code stayed mole because the logic is about the role, not the animal.

Bay two: rules a player cannot see

The same hole is never picked twice in a row. Only one chain of appearances runs at a time, so the pace cannot double up. A hit hides the creature at once, so one appearance can only score once, and clicks sent by a script do not count, because the game checks that the click came from a real press. Pressing start during a round does nothing. When time ends the board freezes behind the final score panel, and Play Again starts again from zero.

Prize ticket: scripted clicks are refused. The game checks that each click came from a real press.

Bay three: the high score board

The board is optional. The page looks for Firebase configuration supplied by its hosting environment, including a global config value and related settings. When that configuration exists and sign in and the database are ready, the game saves only the best score for each player, one record per player, and a weaker round never overwrites a stronger one. When no configuration is present, which is the case for the plain file opened on its own, the game plays identically and scores are saved nowhere.

Prize ticket: no configuration, no saved scores. The round itself plays the same either way.
