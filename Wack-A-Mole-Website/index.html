Ticket 2: Rules

How the game works

I built the whole game as one file, Wack.html. A single chain of peep calls runs the moles. One mole comes up at a time, in a hole that is never the same hole twice in a row. When its time runs out it goes back down and the next one comes up. A whack hides the mole at once but does not touch its timer, because clearing that timer would kill the chain and stall the round while the clock kept running.

  • Board: 9 holes in three rows of three.
  • Round: 30 seconds, counted down once per second.
  • Mole time up: a random draw from randomTime(500, 1500), so half a second to a second and a half.
  • Scoring: one point per whack, and one whack per appearance.
  • In Wack.html the mole figure is a hedgehog. I had no mole I liked at that size, and the class name stayed mole because the logic is about the role, not the animal. On this page I drew the mole with plain CSS shapes instead.

The timing code, from Wack.html

From Wack.html, lines 415 to 417, the function itself:

        function randomTime(min, max) {
            return Math.round(Math.random() * (max - min) + min);
        }

From Wack.html, line 443, the call that sets how long a mole stays up:

            const timeToPop = randomTime(500, 1500); // I keep a mole up for half a second to a second and a half. Shorter felt unfair in my testing of the pace, longer felt slow.

I use those same two bounds in the board above. If the numbers in Wack.html ever change, this page should change with them.

Ticket 4: Notes

Project history and honest notes

The game started as a single file because I wanted something a person could keep, send, and open without a setup step. That choice still shapes everything here, including this site, which is also a single file.

An honest note about a bug I am glad was caught: in the deep improvement pass, a double-scoring bug was found and fixed. The auth callback could run the setup more than once, a second listener stacked on the grid, and each whack scored twice. The setup now guards itself so it runs once, and the board above follows the same rule: one listener, one point per appearance.

An honest note about scores: the high score board is optional and inactive without hosting-supplied Firebase configuration, so scores are not saved in the plain file. Open Wack.html on its own and the game plays in full; the round ends, the final score shows, and nothing is stored anywhere. I would rather say that plainly than let a score board imply saving that is not happening.

An honest note about timing: the only timing numbers I claim are randomTime(500, 1500) from the file itself, half a second to a second and a half per mole. I did not round them, rename them, or borrow numbers from any other version of this game.

An honest note about this page game: it is my page version of the same rules, written for this page. It saves nothing and phones nothing. Your score lives in the readout until you close the tab.
